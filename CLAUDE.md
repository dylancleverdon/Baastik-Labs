# Baastik Labs: notes for Claude

- One folder per plugin under `plugins/`. Each plugin has its **own** workflow
  (`.github/workflows/<plugin-id>.yml`, path-filtered), its own `VERSION`, its
  own GitHub environment and release channel (`<plugin-id>-latest`), and its own
  installer under `packaging/<plugin-id>/`. Keep them isolated: never make one
  plugin's workflow build or release another.
- Develop each plugin on its own branch (e.g. `claude/serum-preset-generator-*`).
- Shared code: `libs/` (no JUCE) and `modules/` (JUCE modules, e.g. `baastik_updater`).
- Build and test without JUCE:
  `cmake -S . -B build -DBAASTIK_BUILD_PLUGINS=OFF && cmake --build build && ctest --test-dir build`
- Serum preset generation content is JSON in
  `plugins/SerumPresetGenerator/Resources/content`; `tests/test_content.cpp` validates it.
  Content-only changes ship as a hot update (no reinstall).
- `libs/serum2/data/*.json` is generated by `tools/schema_export/export_schema.py`; don't hand-edit.
- Never commit presets from commercial sample packs.
- Text To Synth (`plugins/TextToSynth`, branch `text-to-synth`) is a Claude plugin
  (stdio MCP server), not an audio plugin. `core/` is JUCE-free and tested in
  `tests/test_text_to_synth.cpp`; `Source/` adds the JUCE updater; `dev/` builds
  `text-to-synth-dev` without JUCE. Its vocabulary is
  `plugins/TextToSynth/Resources/content/vocabulary.json` (a test checks every
  name in it resolves) and ships as a hot update like the generator content.
- Test edits against a real preset library without committing it:
  `SERUM_FIXTURES=<folder> ./build/tests/baastik_tests` (subfolders included).
