# Serum 2 preset format notes

Serum 2's `.SerumPreset` format is not documented by Xfer. This is what
`libs/serum2` relies on: community reverse-engineering (0xdevalias,
KennethWussmann/serum-preset-packager, serum-mcp) plus our own checks against
presets saved by Serum 2.0.22–2.0.24.

## Container

```
"XferJson\0"                     9 bytes
u32le metadataLength, u32le 0
metadataLength bytes of JSON     presetName, presetAuthor, tags, hash, ...
u32le cborLength, u32le 2        cborLength = size after decompression
zstd frame                       CBOR-encoded engine state
```

Verified here:

- **`hash`** in the metadata is the **MD5 of the zstd frame** (the compressed
  bytes). `encodePreset` recomputes it.
- **Every CBOR map is written with its keys sorted**, including the metadata JSON.
  We use key-sorted `nlohmann::json`, so decode + encode reproduces Serum's
  bytes exactly (`tests/test_preset_file.cpp` checks this on every fixture).
- **Floats use the shortest exact encoding**: float32 when lossless, otherwise
  float64, never float16. Integers use their shortest form. This matches
  nlohmann's CBOR writer.

## Payload rules the editor follows

- Inside `plainParams`, every number is a double: booleans are `1.0`/`0.0`, and
  never CBOR bools or ints (serum-mcp found that CBOR bools crash Serum).
- A module whose parameters are all default stores `"plainParams": "default"`.
- **Leaving a key out is not the same as writing its default.** Serum skips some
  DSP stages when a key is absent, so the editor removes keys that equal Serum's
  absent value, and FX units leave out `kParamWet` when it is 100.
- LFOs are beat-synced at 1/4 when `kParamBeatSync`/`kParamRate` are absent.
  Setting `kParamBeatSync` to 0 switches to Hz, where raw `kParamRate` is Hz.
  Synced rates we've measured: 4 bar 0.2108, 1 bar 1.6269, 1/2 3.3736,
  1/4 6.25, 1/8 10.66, 1/16 17.0788, 1/32 26.0308.
- Changing an LFO's mode writes `kParamMode` along with `kParamDefaultMode: 0.0`.
- LFO shapes live in `curveData`: `numPoints` = points − 1, `yVals` are inverted
  (0 = top), and `curveVals` 0.5 is a straight segment.
- Choosing a noise type (White/Pink/Brown) drops `relativePathToNoiseSample`.
- Wavetables are referenced by path and need the exact `numFrames`,
  `sampleRate` and `numChannels` Serum recorded for that file. `serumtool scan`
  extracts these from your own presets, so more tables can be added to the
  schema.
- Mod slots: `source: [id, auxId]`, `destModuleTypeString/ID/ParamName/ParamID`.
  FX destinations use `destModuleID = rack * 100 + position`.

## Where the tables come from

`libs/serum2/data/*.json` is generated by `tools/schema_export/export_schema.py`
from serum-mcp's MIT-licensed parameter tables (pinned commit), plus the
corrections above. Regenerate it with that script. Don't edit the JSON by hand.

## Known unknowns

- Which frames of the factory wavetables are which shapes (only a few are
  confirmed, see `knownFrames` in the schema).
- Mod amount scaling for pitch and octave destinations.
- Granular and spectral engines aren't generated yet (the format is known, but
  they need sample references).
